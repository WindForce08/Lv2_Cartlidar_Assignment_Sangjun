# 듀얼 OpenCR 프로토콜 v4

> **이력 문서 (v4 · 6륜 기준).** 현재 펌웨어는 v5 · 주행 4륜이다 —
> 사용법은 [`ros2_ws/src/opencr_firmware/README.md`](../ros2_ws/src/opencr_firmware/README.md),
> 규격 변경 요청은 [`opencr_v5_change_request.md`](opencr_v5_change_request.md). 아래 "Arduino IDE 에서 `OPENCR_BOARD_ROLE` 값을 바꿔 빌드" 는
> 더 이상 쓰지 않는다 (역할은 빌드 옵션으로만, `tools/build_firmware.sh`).

## 목표

Jetson Orin Nano는 USB CDC를 통해 두 개의 OpenCR 보드와 통신합니다. 한 보드는 속도 모드(Velocity Mode)의 바퀴 Dynamixel 6개(ID 1–6)를 담당하고, 다른 보드는 위치 모드(Position Mode)의 매니퓰레이터 Dynamixel 6개(ID 11–16)를 담당합니다. 호스트는 USB 열거 순서나 물리 포트 위치가 아니라 프로토콜 역할을 기준으로 각 보드를 식별합니다.

## 프레임 및 호환성

프레임 형식은 `FF FD | TYPE | LEN | PAYLOAD | CRC16-LE`를 유지합니다. CRC는 헤더의 두 바이트, 타입, 길이 및 페이로드를 대상으로 계산합니다. 여러 바이트로 이루어진 값은 모두 리틀엔디안이며, 실수는 IEEE-754 float32 형식을 사용합니다.

프로토콜 버전은 **4**입니다. v3 프레임은 이전 페이로드 길이를 사용하므로 v4 파서에서 거부됩니다. 호스트는 활성화 전에 펌웨어 버전이 모두 4인 최신 `ROLE_WHEEL` 상태와 `ROLE_ARM` 상태를 각각 하나씩 받아야 합니다. v3 통합 보드 펌웨어는 호환되지 않으므로 듀얼 보드 호스트와 함께 사용하면 안 됩니다.

역할 값은 `ROLE_WHEEL = 1`, `ROLE_ARM = 2`입니다. 각 명령에는 대상 역할이 지정됩니다. 펌웨어는 다른 역할을 대상으로 한 명령을 폐기하고 `ERR_ROLE_MISMATCH` (`0x20`)를 보고합니다.

## 페이로드 레이아웃

| 프레임 | 페이로드 바이트 수 | 필드 |
|---|---:|---|
| CMD `0x01` | 55 | role (1), `wheel_vel[6]` (24), `arm_pos[6]` (24), `gripper_pos` (4), flags (1), seq (1) |
| STATE `0x81` | 192 | role (1), `pos[12]` (48), `vel[12]` (48), `effort[12]` (48), quaternion (16), gyro (12), accel (12), battery voltage (4), error (1), firmware version (1), seq (1) |

공유하는 12개 관절 상태 레이아웃은 변경되지 않았습니다. 바퀴 슬롯은 0–5, 팔 슬롯은 6–11입니다. 바퀴 보드는 바퀴 슬롯만 채우고, 팔 보드는 팔 슬롯만 채웁니다. IMU와 배터리 상태는 바퀴 보드가 호스트에 제공합니다. 팔 보드는 해당 필드를 0으로 보고합니다.

## 펌웨어 역할

`OPENCR_BOARD_ROLE=1`로 바퀴 보드 이미지를 빌드합니다. Arduino IDE에서 팔 보드 이미지를 컴파일하기 전에는 `config.h`의 `OPENCR_BOARD_ROLE` 값을 `2`로 설정합니다. 설정되지 않은 빌드가 팔 보드 이미지로 잘못 만들어지는 일을 막기 위해 기본값은 바퀴 역할입니다. 바퀴 이미지는 ID 1–6을 속도 모드로 초기화하고, 팔 이미지는 ID 11–16을 위치 모드로 초기화합니다. 각 이미지는 자신이 담당하는 Dynamixel만 읽고 씁니다.

`config.h`의 바퀴 방향 값은 왼쪽 앞/가운데/뒤, 그다음 오른쪽 앞/가운데/뒤 순서의 슬롯을 따릅니다. 이는 소프트웨어 기본값이며 실제 모터의 물리적 회전 방향을 검증한 값은 아닙니다. 모터에 전원을 넣어 움직이기 전에 각 방향을 확인해야 합니다.

## 호스트 동작

`OpenCRHardware` 인스턴스 하나가 `ports` 매개변수에 지정된 후보 장치 경로 두 개를 엽니다. 기본값은 `/dev/ttyACM0,/dev/ttyACM1`입니다. 호스트는 두 스트림을 읽고 STATE에 보고된 역할을 기준으로 각 포트를 연결하므로 ACM 번호가 바뀌어도 관절 연결이 뒤바뀌지 않습니다. 역할이 중복되거나 누락된 경우, 또는 펌웨어 버전이 4가 아닌 경우에는 동작을 거부합니다.

동일한 호스트 하드웨어 구성 요소가 바퀴와 팔 인터페이스 전체 및 기존 래치형 E-stop 로직을 관리합니다. 링크 하나라도 오래된 상태가 되면, 호스트는 연결 가능한 보드에 E-stop을 전송합니다. 연결이 끊긴 보드는 기존의 200 ms 명령 시간 초과 로직에 따라 자체적으로 정지합니다. 활성화 시에는 두 역할의 상태를 모두 기다린 뒤 팔 보드의 현재 위치를 기준으로 팔 명령값을 초기화합니다.

## 검증 범위

소프트웨어 검증에서는 페이로드 길이, 역할 왕복 처리, 역할 인식 루프백, 버전 불일치 시 활성화 거부, 오래된 링크 처리 등을 확인할 수 있습니다. 현재 환경에는 Jetson과 OpenCR 보드는 있지만 Dynamixel이나 다른 모터 하드웨어는 없습니다. 따라서 모터에 전원을 넣는 시험, 회전 방향 확인, E-stop 배선 확인, 실제 액추에이터를 이용한 플래시 검증은 해당 부품을 사용할 수 있을 때까지 범위에 포함되지 않습니다.
