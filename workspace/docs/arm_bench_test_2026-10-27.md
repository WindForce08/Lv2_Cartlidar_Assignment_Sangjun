# 팔 OpenCR 실기 시험 기록 (2026-10-27, Firmware 팀)

이전 기록: [arm_bench_test_2026-10-26.md](arm_bench_test_2026-10-26.md). 팔 OpenCR 1대를 PC 에 직접 연결해 (Jetson · 주행 보드 없이) 진행했다.
장치 쓰기 (업로드 · 모터 EEPROM · 토크 · 이동) 는 단계마다 승인을 받았다.
작업은 개인 시험 폴더 (`~/GIT/arm_bench`, 이 저장소 `4cc4569` 사본 + 슬라이더 · 모니터 · 시험 스크립트, 저장소 밖) 에서 하고, 끝난 변경만 이 저장소로 옮겼다.

같은 날 1안 차체 (`cartridar_01` CAD URDF) 가 폐기되어 로봇 URDF 를 지웠다 (`opencr_v5_change_request.md` "로봇 URDF — 차체 2안 대기"). 팔 설계는 그대로다.

## 1. 바뀐 설정 (실물 모터 · 펌웨어 `config.h`)

| 관절 (ID) | 펌웨어 범위 [rad] | 모터 EEPROM 위치 한계 [tick] | 비고 |
|---|---|---|---|
| J1 (11) | −π ~ π (±180°) | 0 ~ 4095 | 배선 꼬임 확인 필요 ★ |
| J2 (12) | −2.14 ~ 1.6 | 653 ~ 3091 | 대기 자세 691 tick 포함 (A안) |
| J3 (13) | −1.6 ~ 1.60 | 1005 ~ 3091 | 대기 자세 3057 포함 |
| J4 (16) | −1.92 ~ 2.0 | 796 ~ 3352 | 대기 자세 835 포함 |
| J5 (14) | −2.8 ~ 2.8 | 223 ~ 3873 | 그대로 |
| 그리퍼 (15) | −0.7946 ~ 0.9541 | 1530 ~ 2670, **PWM Limit 400 (45 %)** | 다시 결합 (아래), Homing Offset 0 |

- 대기 자세 (전원을 끄기 전 접어 두는 자세): J1 1008 · J2 691 · J3 3057 · J4 835 · J5 2039 · 그리퍼 2650 tick. 이제 이 자세에서 바로 토크를 켤 수 있다.
- 그리퍼 다시 결합: 0/4095 경계를 지나던 결합 (10-26 4-4) 을 열린 상태에서 다시 맞춤 → **열림 1550 · 닫힘 2650 tick** (닫을수록 증가, 이동 1100 tick).
  펌웨어 범위는 양 끝 20 tick 여유 (닫힘에서 읽는 값이 조금씩 흔들려도 시작 검사를 통과).
- Homing Offset 으로 맞추는 방법은 쓰지 못함: 위치 모드에서는 ±1024 만 받는다 (2048 을 써도 무시됨 — 시험, 전원을 껐다 켜도 같음).
- `tools/dxl_setup` 에 `o <id> <offset>` (Homing Offset) · `w <id> <pwm>` (PWM Limit) 추가 (둘 다 토크 OFF 필요, 다시 읽어 확인).

## 2. 수동 조작 (슬라이더) 과 과부하

- 시험 폴더의 슬라이더 (J1~J5 · 그리퍼 mm, 속도 한계, 정지 = ESTOP · 추종 오차 감시) 로 관절 · 그리퍼 개폐 · 퍽 집기 · 놓기를 해 봄 → 오류 비트 없이 됨 (사용자).
- 그 전에 퍽을 쥐다가 `CMD_TIMEOUT | MOTOR_HW`: 그리퍼가 퍽에 막힌 채 PWM 100 % 로 약 1.5 s 밀어 과부하로 추정.
  확인 전에 전원을 껐다 켜서 Hardware Error Status 가 지워져 어느 모터였는지는 모른다 (다음엔 전원을 끄기 전에 `dxl_setup r <id>`).
- 대응: 그리퍼 모터 PWM Limit 885 → 400, 펌웨어 그리퍼 막힘 보호 (3장).

## 3. 펌웨어 변경 — 그리퍼 막힘 보호 · 부팅 점검

- `safety_core.h` `GripGuard` · ino `guardGripper()` (명령 적용 뒤 · SyncWrite 전, HOLD 중에도 — 무수신 HOLD 는 마지막 목표를 유지해 닫던 그리퍼가 계속 조일 수 있음):
  그리퍼 목표가 현재보다 `GRIP_STALL_TICKS` (45) 넘게 앞서 있는데 `GRIP_STALL_MS` (300 ms) 동안 `GRIP_PROGRESS_TICKS` (8) 도 못 움직이면 = 막힘
  → 목표 = 막힌 자리 + `GRIP_SQUEEZE_TICKS` (33) 로 고정. 호스트 목표가 그보다 덜 닫는 쪽이면 풀고 따른다.
  빈 손으로 멀리 움직이는 중에는 (계단 명령이라도) 계속 움직이므로 막힘이 아니다.
- ESTOP · 토크 OFF 요청 HOLD 때 그리퍼 목표가 현재에서 45 tick 안이면 (쥐는 중) 그대로 둔다. 현재 위치로 바꾸면 쥐는 힘이 0 이 되어 퍽을 놓칠 수 있다.
- 부팅 점검에 그리퍼 PWM Limit ≤ `GRIP_PWM_LIMIT_MAX` (400) 추가 — 공장값 885 면 FAULT (토크를 켜지 않음).
- 힘: 그리퍼 위치 P 800 기준 1 tick ≈ PWM 6.25 → 쥘 때 33 tick ≈ PWM 206 (23 %). 호스트가 문턱 안으로 직접 조이면 최대 45 tick ≈ PWM 281 (32 %).
- 프로토콜 (v5) 필드는 그대로. 호스트가 볼 표시 비트는 없다 (그리퍼 위치가 명령보다 덜 닫히고 전류가 있으면 쥐는 중).
- 호스트 명령 한계 (`opencr.ros2_control.xacro`) 를 새 펌웨어 범위로 (로봇 URDF 를 지워 URDF 쪽 제한이 없어짐).
- 바이너리: 팔 `opencr_arm_v5.bin` sha256 `986ad2ba5be64119…` (보드에 올라감), 주행 `6613c10a871f3779…` (올리지 않음, 동작은 그대로 — 같은 소스를 공유해 sha 만 바뀜).

## 4. 시험

### SIL (`colcon test --packages-select opencr_hardware`)

- 86 개, 실패 0, 건너뜀 1 (로봇 URDF 시험 — URDF 없음, 차체 2안 대기).
- 새 시험: 그리퍼 막힘 → 약하게 쥠 · 빈 손 계단 명령은 막힘 아님 · ESTOP / 무수신 HOLD 에서 쥔 채 · 부팅 PWM 점검 · `GripGuard` 단위 시험.
  보호 코드를 하나씩 빼면 (보호 호출 · ESTOP 유지 · PWM 점검 · 움직임 판정) 해당 시험이 실패하는 것도 확인.
- 처음 (바꾸기 전) 에는 80 개 중 2 개 실패 = 호스트 그리퍼 명령 한계 (−0.83 ~ 1.27) 가 다시 결합한 펌웨어 범위 밖 → 고침.
- SIL 은 실제 펌웨어 소스를 PC 에서 가짜 모터와 돌린다 — 실물 모터 동작을 보장하지 않는다 (그래서 아래 실물 시험).
