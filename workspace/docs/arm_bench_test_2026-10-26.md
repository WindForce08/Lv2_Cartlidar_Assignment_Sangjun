# 팔 OpenCR 실기 시험 기록 (2026-10-26, Firmware 팀)

팔 OpenCR 1대를 PC 에 직접 연결해 (Jetson · 주행 보드 없이) 모터 사전 설정 → 펌웨어 업로드 → 관절별 저속 이동을 했다.
장치 쓰기 (업로드 · EEPROM · 토크 · 이동) 는 단계마다 승인을 받고 진행했다. 결과 요약 · 알려진 문제 · 다음 순서를 남긴다.

## 1. 환경

- PC (x86_64 Ubuntu 24.04) ↔ USB ↔ 팔 OpenCR ↔ 팔 Dynamixel 6대. 포트 권한: `dialout` + `opencr_hardware/udev/99-opencr.rules`.
- OpenCR 이 업로드 때 부트로더로 자동 전환되지 않음 → 매번 **Recovery Mode** (PUSH SW2 누른 채 Reset) 로 업로드.
- 도구: `opencr_firmware/tools/dxl_setup` (모터 설정 · 진단), `opencr_hardware/scripts/opencr_arm_tool.py` (STATE 감시 · 저속 이동).
- 물리 E-stop 없음 — 비상시 OpenCR 전원 차단 (모터 전원이 OpenCR 을 거쳐서 따로 끌 수 없음, 끄면 팔이 떨어지므로 받친 뒤).

## 4. 발견한 문제와 조치

1. **모터 EEPROM 위치 한계가 펌웨어 범위보다 좁으면 모터가 목표를 조용히 버린다** (joint2 2230~3033).
   SyncWrite 는 응답이 없어 펌웨어가 알 수 없었다. → 6대 한계를 `config.h` 범위로 맞추고, **부팅 점검에 위치 한계 검사**를 넣음
   (`checkArmLimits`, 좁으면 MOTOR_CONFIG · FAULT). dxl_setup 에 `x` (진단 덤프) · `m` (위치 한계 쓰기) 추가.
   도구에 **목표 미도달 중단** (`--max-final`, 기본 0.02 rad) · 구간별 최대 전류 출력 추가 — 안 움직였는데 "완료" 로 끝나던 문제.
2. **중력 처짐과 래칫 (미결)**: P 게인만 써서 J2 · J3 가 무게만큼 목표보다 처진 채 버틴다 (버틸 때 J2 0.026 rad, 들어 올릴 때 0.069 rad, 약 13 A/rad).
   게다가 목표를 "현재 위치" 로 다시 잡을 때마다 (도구 시작 · HOLD 진입 · 토크 ON) 그 처짐만큼 더 내려간다 (J2 0.098 → 0.124 → 0.156 → 0.183 rad).
   → 위치 I 게인 · P 게인 · HOLD 정책 중 결정 필요 (I 게인은 막혔을 때 힘이 계속 커지는 위험이 있음).
   결정 (2026-10-26): P 를 조금 올리고 작은 I — 펌웨어가 부팅 때 `config.h ARM_POS_*_GAIN` 을 씀 (구현, 지금은 공장값), 값은 실물 튜닝 (6 장).
3. **6 번째 칸은 gripper_roll 이 아니라 그리퍼 개폐 모터**: 실물 팔 = 허리 · 어깨 · 팔꿈치 · 손목 굽힘 · 손목 롤 + 평행 그리퍼
   (시뮬레이션 `TeamRobot/Sim3D` 의 `teamrobot.urdf` 와 같음). 저장소 URDF · `interfaces.md` · `manipulator.yaml` 은 gripper_roll 로 되어 있음 → 팀 확인 필요.
4. **그리퍼 결합 (미결)**: 한 번 다시 맞췄을 때는 닫힘 1440 · 열림 2945 (열림 = tick 증가) 였는데, 마지막 측정은 닫힘 611 · 열림 −1293 (누적, 열림 = 감소) 으로
   결합이 바뀌어 0/4095 경계를 지난다. Position 모드는 한 바퀴 (0~4095) 안에서만 움직이므로 다시 결합해야 한다 (열린 상태에서 "한바퀴안" ≈ 1100).
   이동량도 측정마다 1427~1904 tick 으로 달라서, 열림 끝이 기구 끝(스토퍼)인지 확인 필요.
5. **전원 켜기 전 시작 자세가 범위 밖 (미결, A안 선택)**: 팔을 접어 왼쪽으로 둔 자세 — J1 3074 (+90°) · J2 690 (−119°) · J3 3056 (+89°) · J4 832 (−107°) · J5 ≈ 2059.
   J2 · J3 · J4 가 펌웨어 · 모터 · URDF 범위 밖이라 도구는 시작을 거부하고, 호스트는 URDF 범위로 자른 명령 때문에 REARM 순간 한계까지 튈 수 있다 (R3).
   → A안: 범위를 시작 자세 + 약 0.055 rad 까지 넓힘 (제안 J2 최소 −2.14 · J3 최대 +1.60 · J4 최소 −1.92 rad ★). config · 모터 한계 · URDF 수정, 아직 안 함.
6. **영점은 대충 맞춘 상태**: J3 · J4 는 눈으로 맞춰 수 ° 오차 가능. 역기구학 · 전체 범위 동작 전에 정밀 영점 (혼 재조립 또는 소프트웨어 보정) 필요.

## 5. 주행 자세 (시뮬레이션 값, 실물 미확인)

`TeamRobot/Sim3D/sim3d.html` 의 `poseFor('drive')` = 그리퍼 끝을 base_link (0.24, 0, 0.16) 에 30° 아래로 두는 역기구학:

| | joint1 | joint2 | joint3 | joint4 | 손목 롤 |
|---|---|---|---|---|---|
| rad | 0 | −1.4356 | +1.1497 | +0.8094 | 0 |
| ° / tick | 0 / 2048 | −82.3 / 1112 | +65.9 / 2798 | +46.4 / 2576 | 0 / 2048 |

시뮬레이션 URDF 의 축 · 치수는 저장소 URDF 와 같다 (순기구학으로 확인). 실물 확인 필요: J2 를 뒤로 82° 젖힐 때 차체 · 케이블 간섭
(시뮬레이션이 이 자세와 겹치는 차체 충돌 상자를 검사에서 빼고 있음), 시작 자세에서 주행 자세로 가는 순서 (J1 +90° → 0, J4 −107° → +46°).
전원을 켜자마자 팔이 저절로 움직이게 하지 않고, 호스트 활성화 → 운용자 REARM 뒤 이동하는 방식을 제안 (실제 시스템은 manipulator_node 담당).

## 6. 다음 순서 (장치 쓰기마다 승인)

1. 그리퍼 다시 결합 · 개폐 범위 측정 → A안 (시작 자세를 범위에 넣기) 적용.
2. 위치 게인 튜닝: 후보마다 `config.h` 를 바꿔 업로드 → `opencr_arm_tool.py move ... --dwell 3 --log 파일.csv` 로 J2 · J3 ±0.1 기록.
   합격 기준 (제안 ★): 1 초 안에 오차 0.01 rad 이하 · 넘침 0.02 rad 이하 · 3 초 뒤 흔들림 0.005 rad 이하 · HOLD 3 번 다시 잡아도 J2 하강 0.005 rad 이하 ·
   HW 오류 0 · 5 분 HOLD 뒤 온도 확인. 후보 (★): P800/I0 (기준) → P800/I100 → P800/I300 → P1200/I300 (I 는 J2~J4 부터).
3. 시작 자세 → 주행 자세 경로를 손으로 확인 → 도구에 `--pose drive` · `--pose start` 추가 → 실물 이동.
4. 정밀 영점, 그리퍼 개폐 시험, Jetson 에서 두 보드로 ros2_control 시험.
