2문서보다 안정 · 효율을 위해 더한 것

E-stop 해제를 한 번으로

팔의 별도 래치 · 리셋 서비스를 없애고 opencr_hardware 의 잠금식 /e_stop 하나만 따릅니다.

리셋을 두 군데서 해야 하던 운용 실수를 막습니다. 관절 · 속도 한계와 공구 높이로 거는 팔의 HOLD 는 그대로입니다.

하드웨어 플러그인에서 토픽 처리 (미결 #1 해결)

Lyrical 은 하드웨어 컴포넌트마다 노드를 줍니다. /joy · /e_stop · /diagnostics 를 그 노드에서 처리하고 100 Hz read · write 와는 atomic 값으로만 주고받습니다.

실시간 루프에서 메모리 할당 · 발행이 없고, safety_node 를 따로 둘 필요가 없습니다.

켤 때는 잠긴 상태

전원을 켠 뒤 리셋 버튼을 눌러야 움직입니다. 조이스틱 없는 벤치 시험은 joy_required:=false.

AprilTag 는 OpenCV 내장

apriltag 라이브러리 없이 aruco 의 tag36h11 사전으로 읽습니다. OpenCV 4.6 · 4.7+ 모두 빌드됩니다.

정렬 검출만 640 폭으로

SEARCH_FRONT | ARM_ALIGN 에서 검출 두 번을 15 Hz 이상 돌리려고 Arducam 검출은 줄인 영상으로 합니다.

오차는 정규화 값이라 해상도와 무관합니다. 태그 읽기는 원본 해상도.

미션표를 시작 때 전부 검사

모르는 장소 · 자세 · 대상, 숫자 모드, 0.10 m 미만 정밀 거리, 스킬 안의 스킬 fallback 은 노드 시작 단계에서 실패합니다.

경기 도중에 오타가 드러나지 않습니다.

pick 재시도 무한 반복 방지

pick 실패로 직전 search 부터 다시 할 때, 실패했던 단계를 넘어선 뒤에만 재시도 횟수를 초기화합니다.

늦게 온 응답 무시

미션이 단계 안 phase 를 바꿀 때 세대 번호를 올려, 취소 · 재시도 · 재개 뒤에 도착한 이전 응답으로 단계가 넘어가지 않게 합니다.

후방 카메라가 없을 때

SEARCH_REAR 가 거절되면 실패로 보지 않고 전방만으로 탐색을 계속합니다.

직선 전진 값 확인

마지막 TFmini 거리로 다시 구한 집기 위치가 원래와 5 cm 넘게 다르면 잘못 잰 값으로 보고 버립니다.

3결정 사항

통신 정의는 동결 상태라, 아래 항목은 docs/interfaces.md 변경으로 처리합니다.

#1

스킬 성공 조건

문서에는 "타임아웃이면 0 속도 후 abort" 만 있어, 정해진 시간 동안 하는 주행(slalom 등)도 항상 실패로 끝납니다. policies.yaml 에 finish_on_timeout 을 넣어 두었습니다 (기본 false = 문서대로). 장기적으로는 정책별 성공 · 종료 조건을 명세에 넣는 것을 제안합니다.

결정 필요
#2

ArmPose 결과에 실패 이유

string message 를 추가했습니다. 미션은 pose · pick · align · skill 의 message 를 상태 reason 에 붙입니다. 예: read_tag 실패: pose TAG_VIEW 실패: 관절 상태 없음

반영
#3

/arm/skill_state · /arm/safety_state

문서 토픽표에 없는 모니터링 토픽입니다. 표에 넣을지 뺄지 정해야 합니다. 지금은 모니터링용으로 남겨 두었습니다.

결정 필요
#4

그리퍼가 정해지기 전의 grasped

그리퍼가 없으면 잡았는지 판단할 수 없어 미션이 계속 재시도합니다. 벤치 시험용으로 gripper.assume_grasped_without_gripper: true 를 두었고, 그리퍼가 정해지면 false 로 바꿉니다.

임시 설정
#5

바퀴 수

4륜으로 확정했습니다 (기본값 그대로). robot_nodes.html 의 6륜 표기(하드웨어 표, ID 1~6, velocity ×6)는 문서 쪽을 고쳐야 합니다.

확정

4검증

이 PC (x86_64, ROS 2 Lyrical) 에는 RealSense · TensorRT · ONNX Runtime · controller_manager 가 없어, 해당 부분은 선택 빌드로 빠진 상태에서 시험했습니다.

단위 시험 48개 통과

  • USB 패킷 · CRC · 펌웨어 사본 일치
  • 가상 시리얼로 펌웨어를 흉내 낸 하드웨어 플러그인 루프백
  • E-stop 잠금 판단, TFmini, 색 검출, 대상 추적, AprilTag 검출 · 자세
  • 정책 명세 · 관측 배치 · fill · 행동 clamp
  • 미션 · 스킬 · 안전 상태머신, 미션표 문법, IK, 정렬 제어, /scan 판정

실행 확인

  • 인식 노드: 모드 비트 조합 수락 · 거부, OFF 처리
  • ⑧ control_container: launch 로 노드 4개 로드
  • 실패 이유 전달: 팔 자세 실패가 미션 상태 reason 에 남음

확인하지 못한 것

  • 펌웨어 보드 컴파일 (Arduino 도구 없음 — 스텁으로 문법만 검사)
  • RealSense · TensorRT · ONNX Runtime 경로 (Jetson 에서 처음 빌드)
  • 실물 로봇 주행 · 팔 동작

통합 시험 — 정상 미션

실제 미션 · 주행 · 팔 노드에 간이 시뮬레이터(로봇 이동 적분 · TF · nav2 · 팔 컨트롤러 · 인식 · TFmini · /scan)를 붙여 돌린 순서입니다.

  1. 태그가 안 보여 30° 씩 두 번 회전 → tag 7 읽음 · 미션표 단계 5개
  2. station_A 로 이동하면서 팔 STOW
  3. search: 옆쪽 물체 발견 → 29° spin 으로 전방이 향하게 → 전방 D435 로 다시 확인
  4. 먼 거리 정렬 범퍼 기준 0.40 m · max(READY 돌출 0.15 + 0.15 + 0.1, 0.3)
  5. READY → 정밀 정렬 TFmini 0.15 m
  6. 스킬 pick_cup_v1 거절(정책 꺼짐) → fallback pick · 목표 출처 ① 정밀 정렬 결과
  7. home 복귀 → DONE

통합 시험 — E-stop 재개

  1. approach 도중 /e_stop → 진행 중 goal 모두 취소 → PAUSED
  2. 잠긴 동안 시작 버튼 → "시작 불가: E-stop" 으로 거절
  3. 해제 뒤 시작 버튼 → "재개: approach 0.15" → 미션표 끝까지 → DONE

  • 진단 무수신 시간 — 발행 확인 뒤 diagnostics.timeout: 3.0
